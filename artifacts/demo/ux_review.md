## 상태 오류 조사
- 복구 전 DB: 김유정 status=auto_pass. 누락(CV-04)을 포함한 6개 이슈 모두 resolved이며 resolved_by가 있었다.
- 확정 원인: 기존 확인 API가 누락 이슈도 해소했고, 상태가 열린 이슈만으로 계산됐다. 서류가 없는 상태에서도 자동 통과가 가능했다.
- 테스트는 임시 DB로 격리되어 있으므로 테스트 잔여 DB라는 증거는 없다. 이전 목록을 본 시점의 UI 응답은 보존돼 있지 않아 목록/상세 차이가 발생한 정확한 시점은 단정하지 않는다.
- 조치: 누락은 실제 제출 기준으로 우선 계산한다. 확인 클릭으로 누락은 해소하지 않는다. 공통 claim_status를 쓰고 목록/상세/챗봇을 같은 읽기 모델에 연결했다.
- 로컬 data/cache/demo-polish/before-demo.db로 백업 후 seed --demo 실행: 고객 시나리오 13건, 서류 29장 복구. 김유정은 보완 요청이다.
