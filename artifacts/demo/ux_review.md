## 상태 오류 조사
- 복구 전 DB: 김유정 status=auto_pass. 누락(CV-04)을 포함한 6개 이슈 모두 resolved이며 resolved_by가 있었다.
- 확정 원인: 기존 확인 API가 누락 이슈도 해소했고, 상태가 열린 이슈만으로 계산됐다. 서류가 없는 상태에서도 자동 통과가 가능했다.
- 테스트는 임시 DB로 격리되어 있으므로 테스트 잔여 DB라는 증거는 없다. 이전 목록을 본 시점의 UI 응답은 보존돼 있지 않아 목록/상세 차이가 발생한 정확한 시점은 단정하지 않는다.
- 조치: 누락은 실제 제출 기준으로 우선 계산한다. 확인 클릭으로 누락은 해소하지 않는다. 공통 claim_status를 쓰고 목록/상세/챗봇을 같은 읽기 모델에 연결했다.
- 로컬 data/cache/demo-polish/before-demo.db로 백업 후 seed --demo 실행: 고객 시나리오 13건, 서류 29장 복구. 김유정은 보완 요청이다.

## 검증과 범위
- 백엔드 pytest **135 passed**, live 1개 제외. Ruff 검사/포맷, 프론트 lint·타입·포맷, `next build --webpack` 통과.
- 타이핑 훅을 실제 소스로 실행한 가상 시계 테스트:50자/초, 건너뛰기 후 재진행 방지, prefers-reduced-motion 즉시 표시 통과. OS 설정을 직접 바꾸지는 않았다.
- localStorage 실패는 예외를 처리하고 메모리 대체로 동작한다. 실제 저장 차단 브라우저 환경은 별도 실측하지 않았다.
- 샘플에 없는 1회량은 추측해서 채우지 않고 —로 표시한다. 기존 데이터/정답/추출 응답은 바꾸지 않았다.
- 처리 중 문서는 누락을 아직 확정할 수 없으므로 처리 중을 보존한다. 추출이 끝나면 실제 누락이 상태 계산보다 우선한다. 이 전이는 단위 테스트로 고정했다.
- 홀드아웃/평가 질문/정답/rubric/지급 판단 가드/KB 원문은 변경하지 않았다. 이번에 제품 성능 평가를 재실행하지 않았고 UI 검수를 성능 향상 수치로 주장하지 않는다.
- 최종 DB는 기본 시연 13청구/29서류로 복구했다. 김유정은7/8·보완 요청, 검수 중 모의 요청0건, 진행 단계도0으로 복원했다. 복구 전 DB는 로컬 캐시에만 백업한다.
- Upstage 외부 HTTP **0회**, 문서 전송0페이지, 추가 추정 비용 **$0**. 실제 콘솔 청구액은 조회하지 않았다. 현재 서버는 정상 실행 모드로 되돌려 두었다.
