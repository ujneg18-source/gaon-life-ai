# 시연 답변 형식·말투 검증 (2026-10-16)

## 변경 범위

청구 검토는 고객/청구/서류/저장 이슈에서 합쇼체 문단을 조립한다. 특정 질문 문장이나 고객별 답변을 하드코딩하지 않았다. 같은 진단서의 세분류 누락과 병리 부합 확인을 묶되 원본 이슈·참조는 보존한다. 확인 필요, 보상 제외 가능성, 안내 순서로 표시하고1일 차이를 불일치로 보지 않았음을 명시한다. 수술확인서 보완 사유는 실제 세부내역서 수술명에서 읽는다. 미접수 건은 서류가 없다고 안내하고 자동 통과로 표시하지 않는다.

일반 보험 용어(이관/지급 심사 등)는 유지한다. 내부 식별자는 본문에서 숨기고, 가운뎃점은 청구 검토 제목의 서류명 나열만 허용한다. 다른 의도는 해요체를 유지하며 고객에게 보낼 보완 문자 원문은 기존 표준 템플릿을 보존한다. 기존 보완 초안 분기도 검토 내용 뒤에 남겼다. 거절은 지급 매뉴얼10장/개인정보9장1개 근거와 이유·대안을 표시한다. 맥락이 있으면 남은 항목을 짧게 요약하고, 없으면 [남은 확인 항목 보기]를 제공한다.

화면은 안전한 React 텍스트 노드로 문단을 나누고, 제목을 굵게, 근거 괄호를 연하게 표시한다. 실제 DOM에서8블록/굵은 제목5개/문단 간격10px/본문 rgb(29,26,43)/근거 rgb(98,93,124)를 확인했다. 긴 답변은 기존 대화 영역에서 스크롤하며 추가 하단 캡처도 보존했다.
