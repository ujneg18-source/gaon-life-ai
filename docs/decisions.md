### T-07~11 확정 구현 방침 · 질문 (2026-10-15)
- 사용자 확정에 따라 Agents v2 업로드·폴링 대신 Classify → Parse → Extract 기능별 v1 동기 API를 쓴다. 기존 UPSTAGE_BASE_URL이 v2여도 기능 클라이언트에서 v1 경로로 맞춘다. 스레드형 백그라운드 작업으로 API 응답 대기를 분리한다.
- 성공 응답은 파일 SHA-256 + 단계·모델·스키마·옵션 키로 항상 재사용한다. USE_CACHED_RESULTS=true는 캐시 미스 시 외부 호출 금지다.
- 페이지 예산 30은 실제 usage보다 보수적인 예약 상한이다. 실패·재시도에도 페이지 수를 예약하고 캐시에 장부를 보존한다. 연결 실패·429만 제한 재시도하며, 응답 유실/읽기·쓰기 타임아웃은 pending을 남겨 자동 재과금을 막는다. 서버의 idempotency 보장 없이 중복 과금을 완전히 증명할 수 없어 모호한 요청은 수동 확인 대상이다.

- T-09 형식 검증 실패는 format 이슈 1개로 기록하며 같은 필드에 low_conf를 중복 생성하지 않는다. 신뢰도 설정을 끄더라도 format·교차검증은 강제한다.
- CV-03은 C18.7의 시연용 병리 진단/검체 참조어 대조만 수행한다. 일반 임상 적합성을 판정하는 모델이 아니며 참조가 없거나 부합을 확인하지 못하면 담당자 확인 이슈로 보낸다. CV-06은 계약 보장 기간 데이터가 없어 이번 범위에서 실행하지 않는다.
- 시드 증권번호는 가상 패턴 L-2026-000001을 보존한다. _claim.json의 L-2023-118203과 다르지만 이번 규칙에는 계약기간·증권번호 대조를 포함하지 않는다.

- T-11은 작업 상태의 재시작 복구·청구당 동시 실행 차단을 위해 process_jobs 테이블을 추가했다(부분 유일 인덱스). 프로세스 메모리 상태만으로 완료를 표시하지 않는다. 단일 서버 BackgroundTasks이며 분산 작업 큐는 T-19 이후 확장 사항이다.
- 실제 입력·정답 평가를 분리한다. 검증 스크립트는 실행 엔진에 정답을 전달하지 않고, 처리 후 내용 해시로 각 원본과 정답을 연결한다. 유료 검증 DB는 캐시 아래 격리하고 결과는 입력 폴더/입력 내용 지문별로 보관한다.
- 실측에서 Extract word 좌표가 단어 다각형 배열이고 Classify additional_values.arguments가 객체임을 확인해 파서를 보완했다. 보완 후에는 캐시 전용 재생만 수행했으며 신규 호출은 없다.
- 실제 PNG의 질병코드 고신뢰 오독(C18.7→C18)과 병리 진단 한글 설명 추가는 정답 비교에서 불일치로 유지한다. CV-03 추가 확인 1건과 covered low 4건을 숨기거나 정답으로 교정하지 않는다.

### A 보완 근거 (2026-10-15)
- 진단서 Parse도 C18로 읽혀 단일 원문만으로 세분류 누락을 확인할 수 없었다. 같은 청구의 다른 제출 문서 Parse에서 더 긴 동계열 코드를 확인해 원문 불일치로 보낸다. 추출값은 자동 수정하지 않는다.
- 급여 구분은 유일하게 매칭되는 Parse 표 행의 구분 칸만 사용한다. 이름이 중복되거나 구분 칸이 없으면 모델 low를 유지한다. 별도 Parse 판단을 모델 high로 기록하지 않는다.
