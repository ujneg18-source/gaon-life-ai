# 테스트 결과 보고서 · T-18

## 목적
보험금 서류 검토 챗봇의 의도·검색·인용·거절·답변 요지와 문서 추출 및 오류 검수 표시를 평가한다. 개선 전·중간·최종 실패를 숨기지 않고 남긴다. 아래는 배포 승인이나 실업무 성능 보장이 아니다.

## 환경
2026-10-16, Python3.13·FastAPI·SQLModel·SQLite·LangGraph·Qdrant 로컬. Solar Pro4 답변/고정 rubric 채점, Embedding2 검색. 가상 고객10명·청구13건의 운영 DB와 벡터 DB를 복사해 평가했고 운영 데이터는 바꾸지 않았다. 실제 회사 약관 reference/는 제외했다. 외부 전송 자동 승인 거절 후 사용자가 가상 질문·고객/청구/서류 맥락·공개/가상 약관의 Upstage 전송을 명시 승인한 뒤 실측했다.

## 방법
- 각 라운드 동일30문항·같은 정답 해시·같은 rubric. before → after_v1 → after로 전부 보존했다. 채점기 결과는 score0/1과 사유다. 후속3문항(recheck), 진단1문항(diagnostic)은 전체 점수에 섞지 않았다.
- recall@3는 원문 질문을 독립 검색해 얻은 상위3의 기대 문서·조항 포함 비율을 문항별 평균한 값이다. 기대 근거 없는6문항은 분모 제외(24문항). hit@3도 별도 기록했다. 에이전트가 재작성한 검색은 search_trace로 별도 보존했다. 짧은 특약의 추가 문맥으로 답변이 맞아도 독립 top3에는 실패할 수 있다.
- 인용 정밀도는 doc_name+article이 expected_sources에 있는 인용 수/전체 인용 수다. 인용이 없으면 분모를 임의로1로 만들지 않으며, 필요한 인용 누락은 문항별 실패로 잡는다. 정답 목록 밖의 관련 약관 추가 인용도 엄격 기준에서 실패한다.
- 원본 refusal4문항만 true, 다른26문항은 false를 엄격 검사한다. 지급 판단 질문 Q20은 이 정답과 기존 거절 규칙이 충돌해 안전한 거절을 유지하면서 원점수에는 실패로 남겼다.
- 금지 표현은 지급됩니다/지급 가능합니다 및 개별 지급액 단정 패턴이다. 일반 약관 비율·한도 인용은 분리했다. 의미상 모순은 사람이 별도 확인했다.
- 문서는 정답 스칼라에 같은 날짜·코드·금액 정규화를 적용해 엄격 일치 비교했다. 정답에 없는 선택 필드는 분모 제외다. 실제 API65항목을 실손24 모의 포함190항목과 분리했다. 오답을 양성으로, 확인 필요(review_reasons 또는 해당 FIELD-* 이슈)를 예측 양성으로 정의했다. 업무상 CV 불일치는 추출 오류 검수에서 제외했다. 0분모는 N/A다.

중간보다 최종 요지 점수가 떨어졌다. 검색 보강·추가 문맥이 생성 품질을 일관되게 올리지 않았고, 모델/채점 변동도 관측됐다. 좋은 중간 점수만 최종 성능으로 선택하지 않았다.

Q08의 `2.`와 Q18의 하위제목 `수술확인서`를 실제 payload `2장`으로 수정한 별도 재채점: recall@3 70.83%, 인용47.50%. 동일 응답에 라벨만 바꾼 값이며 새 모델 실행이 아니다. 원본30문항 결과는 그대로 보존했다. 수정된 정답으로 재실행할 때는 새 출력 폴더를 사용한다.

|---|---|---|---|---|

추출 추가 호출0. C18.7→C18은 다른 제출 서류 Parse와 대조해 세분류 누락으로 검출했다. 단일 진단서 Parse도 C18로 읽어 단일 문서 원문 대조만으로는 검출하지 못했다.

자동 테스트71 passed/live1 deselected, Ruff·포맷 통과. 프론트 lint/typecheck/format 통과. 배포 빌드는 Turbopack의 보조 포트 권한 오류가 발생했고 Webpack 대체도 정체되어 성공 확인을 하지 못했다. Node24/26 및 임시 worker 비활성화도 시도했으며 임시 설정은 복원했다. 현재 기존 실행 서버의 검토함13건 정상 응답은 브라우저에서 확인했다.

## 한계
- 가상 문서3고객·깨끗한 PNG7장·65항목으로 실제 업무/사진 정확도를 대표하지 못한다. 오류2건의 정밀도100%·재현율50%도 일반화할 수 없다.
- 같은30문항으로 개선했으므로 개발용 평가다. 독립 holdout 검증이 아니며 과적합 가능성이 있다.
- Solar 요지 채점의 자기평가 편향·비결정성·실제 오판을 확인했다. Q04 같은 의미 모순은 금지 표현 정규식0건으로 보장할 수 없다.
- 정답 허용 집합이 좁아 관련 근거 추가 인용도 실패한다. 원문·trace와 함께 해석해야 한다.
- 후속 오류 수정은3문항/진단1문항으로 별도 측정했다. 마지막 전체30문항 이후 추가된 JSON 재시도/번호 검증 보완을 전체30문항 성능으로 과장하지 않았다.
- 현재 검색은 작은 KB 전체 후보를 읽는다. 대규모 운영에서는 서버 측 후보 축소/별도 lexical 인덱스가 필요하다.
- File Search(beta) 비교는 미실행이다. 잔여 크레딧을 확인하지 못해 추가 소비하지 않았다. 우리 방식의 recall·인용 우열을 주장하지 않는다.
