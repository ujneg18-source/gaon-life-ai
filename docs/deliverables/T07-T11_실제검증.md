## 실제 검출 이슈

- CV-04: 수술확인서 미제출.
- CV-01: 진단일 2026-09-18이 병리 보고일 2026-09-21보다 빠름.
- CV-02: 입퇴원확인서 9일 vs 세부내역서 8일.
- CV-03(기대 목록 외): 진단서 C18이 시연용 C18.7 참조에 없어 부합 확인 필요로 남음. 일반적인 임상 부합 판정이라고 주장하지 않는다.
- FIELD-items[0~3].covered: 모델 confidence low. page=-1, word_coordinates=[]로 반환됨.

약관 대조·보상 제외 가능성은 T-16 범위라 평가에서 제외했다. 최종 청구 상태는 supplement이며 지급 판단을 하지 않는다.

## 불일치 2건과 평가 기준

1. 진단서 질병코드: 정답 C18.7 → Extract C18(high). Parse도 C18로 읽어 같은 문서의 원문 대조만으로는 정답성을 보장하지 못했다. 다른 입퇴원확인서에서는 C18.7이 추출됐다.
2. 병리 진단: 원문 영문에 한글 설명 `(중등도 분화 선암)`을 덧붙였다. 의미가 비슷해도 정답 문자열 일치로 처리하지 않았다.

날짜·코드·금액·수술 분류를 정규화하고 텍스트 공백·문장부호·대소문자를 정리해 비교했다. 이번 strict 비교도 37/39로 같다. 정답에 정의된 항목만 분모에 포함하며, 정답에 없는 추가 추출 필드는 점수에 포함하지 않는다. 한 청구의 시연 검증이므로 일반 문서 성능으로 확대하지 않는다.

## 보완 후 (A, 2026-10-15)

- 추가 유료 호출 0페이지. 기존 Classify/Parse/Extract 캐시만 재생했다.
- C18 원문 대조: 같은 진단서의 Parse도 C18이라 진단서 한 장만으로는 세분류 누락을 증명할 수 없다. 같은 청구의 입퇴원확인서 Parse에 있는 C18.7을 독립 제출 원문 근거로 대조해 진단서 필드의 source_found=false, review_reasons=[not_in_source, "원문과 다름(세분류 누락)"]를 남겼다. high 신뢰도와 추출 C18 값은 보존했다. 정답이나 파일명으로 C18.7로 덮어쓰지 않았다.
- 단일 원문의 부분 문자열 사례(C18 vs C18.7)도 동일 사유로 실패 처리한다.
- 약제비 low 4건 원인: Extract가 covered를 boolean으로 추론했지만 위치를 찾지 못해 low/page=-1로 반환했다. Parse 표에는 품명과 구분 칸이 보존되어 있었다. 품명이 유일하게 일치하는 행의 구분(급여/비급여)을 직접 읽어 판단하도록 바꿨다. 원래 모델 응답의 low는 보존하고, 필드는 별도 Parse 검증 근거와 confidence=null로 저장한다(모델 high로 위조하지 않음). 해당 4건은 더 이상 확인 필요로 라우팅하지 않는다.
- 보완 후 활성 이슈 5건: 기존 누락 1·불일치 3(CV-03 포함)·코드 원문 확인 필요 1. 앱 37/39·전자 77/77은 그대로이며 모델 정확도가 개선됐다고 주장하지 않는다.
- 회귀 테스트 33개 통과. 모델 confidence low 여부와 원문 대조로 발생한 확인 필요 여부는 보고서에서 별도로 구분한다.
